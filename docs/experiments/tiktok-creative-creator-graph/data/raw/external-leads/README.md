# External Lead Lists

Use this folder when token-gated providers are unavailable. The current external acquisition packet is generated by:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/build-external-lead-acquisition-packet.mjs
```

The packet files are:

- `acquisition-packet.csv`: row-by-row acquisition assignments with label, query, rubric, desired lead count, output file name, and import command.
- `acquisition-packet.jsonl`: the same assignments for automation.
- `category-targets.csv`: category gaps and search hints.
- `source-worklist.csv`: one row per concrete TikTok/search URL with a smaller lead quota and the completed file where accepted leads should land.

Break packet assignments into source-level work items with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/build-external-lead-worklist.mjs
```

Use `source-worklist.csv` for contractor/operator assignment. Each work item has a source URL, target label, quota, acceptance rubric, and completed-file path. Leads from multiple work items for the same assignment should be merged into the matching file under `data/raw/external-leads/completed/`.

If operators return one file per work item, save files as `data/raw/external-leads/work-items-completed/<work_item_id>.csv` with the same accepted lead columns. Merge them into assignment-level completed files with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/merge-external-lead-work-items.mjs
```

The merge script reads `source-worklist.csv`, validates work-item ids, dedupes by normalized TikTok handle, and writes assignment-level files under `data/raw/external-leads/completed/` for the existing progress/import pipeline.

Generate fillable per-assignment CSV templates with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/build-external-lead-templates.mjs
```

Templates are written to `data/raw/external-leads/templates/`. Copy a template into `data/raw/external-leads/completed/`, keep the same filename, and fill the blank profile fields. Templates intentionally live outside `completed/` so blank rows cannot be imported accidentally.

Track completed assignment files with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/build-external-lead-progress.mjs
```

This writes `reports/external-lead-progress.md` and `data/processed/external_lead_packet_status.csv`, including missing files, malformed files, underfilled files, duplicate handles, and import-ready commands.

Import every ready, not-yet-imported completed assignment file with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/import-ready-external-lead-packet.mjs
```

The importer writes `reports/external-lead-packet-import.md` and an import ledger at `data/processed/external_lead_packet_imports.jsonl`, keyed by completed filename and SHA-256 so unchanged files are not imported repeatedly.

Drop externally sourced TikTok creator leads here as `.csv`, `.json`, or `.jsonl`, then normalize them with:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/import-external-lead-list.mjs --input=docs/experiments/tiktok-creative-creator-graph/data/raw/external-leads/example.csv --source-name="Contractor film creator search" --target-label=filmmaker
```

Accepted input columns include:

- `handle`, `username`, `profile_url`, `url`
- `display_name`, `name`
- `bio`, `description`, `snippet`
- `target_label`, `category`
- `source_name`, `source_url`, `source_query`
- `follower_count`, `likes_count`, `video_count`, `verified`

The script writes normalized rows into `data/raw/acquisition-results/` so the existing acquisition import and full workflow can ingest them with provenance.

For packet work, save completed lead files under `data/raw/external-leads/completed/` with the `completed_file_name` from `acquisition-packet.csv`, then run that row's `import_command`. After importing completed files, rebuild the graph:

```bash
node docs/experiments/tiktok-creative-creator-graph/scripts/run-full-workflow.mjs
```
