# Grounded QA Distillation

## Question

Given a domain knowledge base that changes over time, can expensive multi-step RAG or agent behavior be distilled into a cheaper model or scaffold while preserving citation-grounded correctness?

This experiment focuses on amortized grounded research rather than generic RAG. The target output is post-training data that teaches a smaller model to:

- answer from a compact retrieved evidence pack,
- cite every factual claim with stable evidence ids,
- abstain when evidence is insufficient,
- emit a structured claim table for verification.

## Dataset Choice

The seed knowledge base is [allenai/qasper](https://huggingface.co/datasets/allenai/qasper) from Hugging Face.

QASPER is a good first dataset because it already has the supervision shape this project needs:

- domain documents: NLP research papers,
- user-style questions written from title and abstract context,
- full paper text for retrieval,
- annotator answers,
- answer evidence spans,
- unanswerable labels.

The Hugging Face Dataset Viewer reports `train`, `validation`, and `test` splits for the `qasper` config. The dataset card describes 5,049 questions over 1,585 NLP papers and lists the license as CC BY 4.0.

## Evolving-KB Setup

The first implementation treated each split as a reproducible knowledge-base snapshot:

- `train`: initial KB version used to construct post-training examples,
- `validation`: later KB version used for held-out scaffold checks,
- `test`: reserved for final evaluation.

The current stronger proxy is generated by:

```bash
node scripts/grounded-qa-distillation-temporalize.mjs
```

It parses arXiv-style QASPER paper ids into inferred publication months and writes month-disjoint, paper-disjoint temporal splits:

- `temporal_train`: oldest papers,
- `temporal_validation`: middle papers,
- `temporal_test`: newest papers.

This is still a proxy for private KB evolution, but it is stronger than treating the original QASPER split names as time. Future versions should replace it with trusted dated metadata, private corpus deltas, or Alpha Research dataset manifests.

## Data Construction

Run:

```bash
pnpm run grounded-qa:distill
```

The generator fetches QASPER rows through Hugging Face's Dataset Viewer API and writes:

- `data/train.jsonl`
- `data/validation.jsonl`
- `data/test.jsonl`
- `data/manifest.json`
- `reports/distillation-data-card.md`

Each JSONL row has:

- `input.question`
- `input.compact_retrieved_evidence_pack[]`
- `input.document_metadata`
- `output.answer`
- `output.citations[]`
- `output.claim_table[]`
- `output.abstention_reason`
- `teacher_trace`

The evidence pack is intentionally compact. It contains QASPER answer evidence plus deterministic hard-negative paragraphs from the same paper. By default, the pack uses stable mixed ordering so the student cannot exploit a gold-first positional shortcut.

Teacher-only evidence roles are stored under `teacher_trace.evidence_roles` for evaluation. They are not exposed in `input.compact_retrieved_evidence_pack`, because that would leak the answer key to a student model.

## Baseline Run

Run:

```bash
node scripts/grounded-qa-distillation-run.mjs --split=validation
```

The run writes:

- `runs/<run-id>/result.json`
- `runs/<run-id>/report.md`
- `runs/<run-id>/*.predictions.jsonl`

Current cheap systems:

- `retrieval_rank_1`: cite the first retrieved evidence item.
- `lexical_overlap_scaffold`: select evidence by question/evidence token overlap and abstain below a threshold.
- `learned_selector_*`: trained logistic evidence selector distilled from teacher evidence roles.

These are controls, not final students. A learned distilled model must beat them on citation precision, answer support, abstention calibration, and cost per accepted grounded answer.

Current run summaries:

- `reports/baseline-results-v1.md`: first small-sample baseline run.
- `reports/student-results-v1.md`: larger pilot with the first learned evidence-selector student.
- `reports/calibrated-results-v1.md`: counterfactual insufficiency, sufficiency calibration, and corrected metrics.
- `reports/compressed-results-v1.md`: phrase-ranked answer compression ablation.
- `reports/temporal-results-v1.md`: month-disjoint evolving-KB proxy evaluation.
- `reports/span-export-results-v1.md`: model-facing SFT export and supervised span-selector ablation.
- `reports/openai-student-results-v1.md`: budget-tracked small generative student pilot.

The claim-pruned strict packet is:

- `exports/teacher-repair-claim-pruner-gpt4o-quote-extractive-132-172-v1.sft.jsonl`
- `exports/teacher-repair-claim-pruner-gpt4o-quote-extractive-132-172-v1.rejected.jsonl`

It contains 33 strict SFT labels from 40 `gpt-4o` claim-pruned examples: 17 answered labels, 16 abstentions, and 7 rejected answered rows. Its full upstream labeling cost is $0.150775 including the pruner and stronger judge, which breaks even against the in-context teacher-demo scaffold after about 212 future queries if inference returns to direct mini-student cost. Because it uses the final available temporal-test window, treat it as a teacher-label construction artifact, not a held-out generalization result.

The first local policy test using this packet is `runs/teacher-label-filter-temporal-test-80-172-v1/`. It trains a zero-LLM logistic keep-answer gate, but the held-out result is negative: the gate improves citation precision and inline citation rate while hurting answer coverage, support, and answer quality. The next useful experiment should train or fine-tune answer generation rather than only suppressing risky answers.

The first hosted fine-tune preparation run is `runs/openai-finetune-prep-teacher-repair-0-80-v1/`. It writes OpenAI chat-format JSONL with 52 train rows and 13 validation rows from the strict teacher-label packet. The current estimate for 3 epochs of `gpt-4.1-mini-2025-04-14` is $0.85656, but the job is not launched until a runner can ledger file/job API calls and actual training spend.

`runs/openai-finetune-teacher-repair-0-80-v1/` is the first launch attempt. OpenAI accepted file uploads but rejected job creation with `training_not_available` for this organization. No job was created, no training spend was ledgered, and the uploaded files were deleted after failure. The next training path should use a local or Hugging Face supervised fine-tuning backend.

`runs/teacher-label-scaffold-temporal-test-80-172-v1/` is the first local teacher-label-only scaffold. It makes no LLM calls, but held-out performance collapses because 65 strict labels are not enough for a non-generative extractor. This result points toward either more repaired-teacher labels or a real generative SFT/LoRA backend.

`runs/teacher-label-scaffold-temporal-test-132-172-v1/` repeats the local scaffold with the expanded 109-label packet and evaluates only on examples 133-172 to avoid train/eval overlap. It remains negative: 5 answered examples out of 40, 90.0% citation precision, 6.5% citation recall, and 4.1% answer F1. More strict labels alone did not make the hand-built extractor a viable amortized student.

`runs/hf-sft-prep-teacher-repair-0-132-qwen05b-v1/` is the first generative student training packet. It prepares 92 train rows and 17 validation rows from `teacher-repair-temporal-test-0-132-v1`, preserves 40 future temporal-test prompts for evaluation, and emits a TRL/PEFT/Trackio Hugging Face Jobs script for `Qwen/Qwen2.5-0.5B-Instruct` LoRA SFT. The generated job uses a public gist data base because the local HF CLI token cannot create datasets and the private GitHub raw files are not anonymously fetchable. The generated CPU validator passes against `https://gist.github.com/rprend/6b46b4b77d7f328cd4e6964884013abe`. Remote HF Jobs execution is blocked until the account has `job.write` plus prepaid Jobs credits. The estimated `t4-small` job bound is $0.5625 for a 45-minute timeout and makes no OpenAI calls.

`runs/hf-sft-prep-teacher-repair-claim-pruner-gpt4o-quote-extractive-132-172-qwen05b-v1/` prepares a second Qwen 0.5B LoRA packet from the claim-pruned labels. It writes 28 train rows, 5 validation rows, and 40 same-window eval prompts. The local dataset validator passes without OpenAI calls. This is launch-ready for overfit and label-quality checks, but not a final held-out experiment because the packet is built from the last temporal-test slice.

`runs/openai-student-teacher-rubric-temporal-test-132-172-v1/` is a runnable fallback while HF training is blocked. It distills the 109 strict teacher labels into a compact static rubric for the cheap `gpt-4o-mini` student. The rubric improves citation precision, inline citation rate, and judged support on examples 133-172, but it over-abstains and loses answer coverage versus direct mini prompting. It is a negative result for amortized quality, but a useful signal that teacher labels transfer citation discipline more easily than answer synthesis.

`runs/openai-student-teacher-balanced-rubric-temporal-test-132-172-v1/` tests a less conservative variant of the same static rubric. It recovers answer coverage and preserves 100.0% inline citation rate and 95.0% overall judged correctness, but still trails direct mini prompting on answer-type accuracy, citation recall, and answer F1. Static rubric distillation is now a citation-format control, not the final student.

`runs/citation-contract-repair-direct-mini-temporal-test-132-172-v1/` is a zero-LLM output-normalization scaffold over the direct mini baseline. It repairs 8 missing inline citation markers across 4 rows and raises inline citation rate to 100.0% without changing answer coverage or answer F1. A fresh judge pass does not prove support preservation, though: overall judged correctness drops to 92.5%, partly from one changed row and partly from judge sensitivity on unchanged rows.

`runs/policy-selector-temporal-test-132-172-v1/` routes locally among direct mini, strict rubric, balanced rubric, and citation-contract repair. It answers 31 of 40 examples and keeps 100.0% inline citation rate, but inherited judged correctness remains 92.5%, below direct mini. Policy routing is useful analysis, not the final student without a stronger verifier.

`runs/verifier-selector-noleak-temporal-test-80-132-to-132-172-v1/` is the first train/eval verifier selector. It trains on judged candidates from examples 81-132 and evaluates on examples 133-172 using only deployable, non-gold features. It remains negative: 31 of 40 answered, 100.0% inline citation rate, and 92.5% inherited judged correctness. The oracle over the same candidates shows headroom, but simple metadata and agreement features do not learn a reliable support-preserving router.

`runs/verifier-selector-evidence-aware-temporal-test-80-132-to-132-172-v1/` adds cheap evidence-alignment features to the same verifier split. It improves answer-type accuracy to 85.0% and citation precision to 80.6% while keeping 100.0% inline citation rate, but inherited judged correctness remains 92.5%. Lexical evidence alignment helps routing, but it is not a sufficient support verifier.

`runs/verifier-selector-evidence-aware-abstention-calibrated-temporal-test-80-132-to-132-172-v1/` adds a train-calibrated abstention override to the evidence-aware selector. It is the current best cheap scaffold: 29 of 40 answered, 87.5% answer-type accuracy, 83.3% citation precision, 100.0% inline citation rate, and 95.0% inherited judged correctness with zero additional LLM calls. It matches direct mini's judged correctness while fixing inline citation compliance, but still trails direct mini on answer F1 and recall.

`runs/verifier-selector-recovery-pool-temporal-test-80-132-to-132-172-v1/` tests an answer-recovery candidate meant to address answerable examples where all previous policies abstain. The recovery candidate improves answer F1 but is unsafe: the recovery-pool selector over-selects it and drops held-out inherited judged correctness to 87.5%. Recovery is now an opt-in diagnostic candidate, not part of the default best scaffold.

`runs/verifier-selector-answerability-guard-temporal-test-80-132-to-132-172-v1/` adds a row-level answerability guard over the best calibrated scaffold. It raises inherited judged correctness to 97.5%, but answers only 25 of 40 examples and loses answer F1. Treat this as a high-safety operating point, not the default balanced scaffold.

`runs/verifier-selector-answerability-guard-coverage-preserving-temporal-test-80-132-to-132-172-v1/` repeats the answerability-guard calibration with a 100% train-window answer-coverage floor. The guard is not selected under that constraint, so the run reproduces the default calibrated selector: 29 of 40 answered, 95.0% inherited judged correctness, and 100.0% inline citation compliance. This is a negative result for coverage-preserving row gating.

`runs/verifier-selector-direct-prior-temporal-test-80-132-to-132-172-v1/` adds a small rank bonus for inline-complete direct-mini candidates. It changes the selected policy mix substantially, but leaves held-out target-good and inherited judged correctness unchanged. This rules out a simple direct-mini prior as the missing support-preserving router.

`runs/verifier-selector-local-entailment-temporal-test-80-132-to-132-172-v1/` adds stricter no-LLM local citation-window features to the verifier. The held-out behavior is unchanged from the calibrated selector, so handcrafted citation-window overlap is not enough to act as the missing entailment verifier.

`runs/openai-judge-gpt4o-verifier-selector-calibrated-temporal-test-132-172-v1/` and `runs/openai-judge-gpt4o-verifier-selector-answerability-guard-temporal-test-132-172-v1/` re-judge the default calibrated and high-safety selector outputs with `gpt-4o`. The stronger judge is harsher than the mini judge: the default calibrated selector scores 82.5% overall judged correctness, while the high-safety guard scores 87.5%. Treat mini-judge-only support claims as optimistic until independently calibrated.

`runs/verifier-selector-gpt4o-train-temporal-test-80-132-to-132-172-v1/` trains the selector target from `gpt-4o` train-window candidate judgments. The held-out selected outputs score only 77.5% under `gpt-4o`, worse than the default calibrated selector and high-safety guard. A single stronger-judged temporal window is not enough to learn a transferable support router.

`runs/openai-student-quote-extractive-temporal-test-132-172-v1/` and `runs/citation-contract-repair-quote-extractive-temporal-test-132-172-v1/` test a stricter quote-near answer candidate. It improves lexical answer F1 to 24.1% and citation precision to 87.2%, but the repaired outputs score only 77.5% under `gpt-4o` judging. This is an answer-quality diagnostic, not a support fix.

`runs/openai-claim-pruner-mini-quote-extractive-temporal-test-132-172-v1/` and `runs/openai-claim-pruner-gpt4o-quote-extractive-temporal-test-132-172-v1/` test claim-level repair over the quote-extractive candidate. After local citation repair, the `gpt-4o` pruner reaches 26.4% answer F1, 90.3% citation precision, and 82.5% `gpt-4o` judged correctness. This is useful for teacher-label construction, but it still does not beat the high-safety guard's 87.5% stronger-judge correctness.

## Evaluation Plan

Compare three systems on held-out examples:

1. Full teacher: retrieval plus a larger model that answers and cites.
2. Distilled scaffold: compact evidence pack plus a cheaper model.
3. Cheap baseline: lexical evidence overlap plus templated abstention.

Primary metrics:

- citation precision: cited evidence actually supports the answer,
- answer support rate: factual claims are entailed by cited evidence,
- abstention calibration: insufficient-evidence questions are refused,
- cost per accepted grounded answer,
- update robustness: performance when validation/test snapshots include papers absent from training.

## Current Scope

This project is not paper-complete. Current artifacts cover deterministic data construction, leakage removal, and cheap scaffold baselines. Required next work:

- replace arXiv-id-inferred temporal splits with trusted dated KB snapshots,
- train or fit a compact generative student on `teacher-repair-temporal-test-0-132-v1.sft.jsonl` and evaluate on future held-out examples,
- create a later temporal/private-KB snapshot before using `teacher-repair-claim-pruner-gpt4o-quote-extractive-132-172-v1.sft.jsonl` for generalization claims,
- run the prepared Hugging Face LoRA SFT packet after remote CPU validation, then evaluate the trained adapter on held-out future examples,
- calibrate the entailment-style citation judge against stronger independent or human judgments,
- evaluate cost/quality tradeoffs against a larger teacher,
- write the paper and threat model.
