From Software Engineer to AI Researcher: A Natural-Method Curriculum

For: a senior software engineer / founder (CS degree, ML course mostly forgotten) who wants to (1) produce novel research results at the level of a research engineer at Anthropic or OpenAI, and (2) read any AI paper and follow it.

Written: June 2026. Links are to stable artifacts (arXiv, GitHub, well-known blogs).

The method (why this is like Lingua Latina)

*Lingua Latina Per Se Illustrata* teaches Latin by having you read Latin that is always ~95% comprehensible — every new word is inferable from context you already have, and one continuous story (the family of Julius) carries you from page 1 to fluency. No grammar tables up front.

This curriculum does the same thing with three rules:

  1. Build before you read. You never read a paper about a thing you haven't already built a small version of. When you finally read *Attention Is All You Need*, it will feel like reading a description of code you wrote last week — because it will be. Papers are the *graded readers*, not the textbook.
  1. One continuous artifact. Your "Familia Romana" is a single small GPT that you build in week 3 and never abandon. Over six phases it gains a tokenizer, gets trained on real web data, gets instruction-tuned, gets RLHF'd, gets a KV cache and an eval suite, and finally gets dissected with interpretability tools. Every phase ends with *your model* able to do something it couldn't before.
  1. Everything must survive the "but what actually IS it?" test. Every concept gets grounded in one of: *a file on disk* (what's in it, how big), *a function* (inputs, outputs, shapes), *a loop* (what runs, for how long, on what hardware), or *a number* (how big, how much, how fast). If an explanation in these notes ever fails that test, that's a bug — the phase files are written so you can always drill to "it's literally an array of floats" level.

The single most important mental model, up front: everything in this field is a *pure function from arrays of numbers to arrays of numbers*, containing millions-to-trillions of tunable constants ("parameters," literally arrays of 32- or 16-bit floats), and "training" is a for-loop that nudges those constants to make one scalar (the "loss") smaller. A "model" on disk is those float arrays serialized into a file. That's it. The entire curriculum is elaboration of that sentence.

Hardware and budget

  • Phases 0–1: your laptop. Everything runs on CPU or an M-series GPU in minutes.
  • Phase 2 onward: rent GPUs by the hour (Lambda, RunPod, Vast). A 4090 is ~$0.40–0.70/hr, an A100 ~$1.30/hr, an H100 ~$2–3/hr. The whole curriculum's training runs cost $150–400 total if you're not careless. Every build section states its expected cost.
  • A "GPU" for our purposes: a card with its own RAM (VRAM, 24–80 GB) and ~100–1000× your CPU's throughput *on matrix multiplies specifically*. Model fits in VRAM or you can't run it — VRAM is the budget you'll constantly compute against.

How to study (the weekly rhythm)

  • Build first (60% of time): the phase's build section, in a repo you keep forever.
  • Then read (30%): only the papers the phase marks as *now readable*. Read with the code open.
  • Then close the loop (10%): each phase ends with a checkpoint — questions and tasks. Do them cold, no notes. If you can't, the phase isn't done. This is the Feynman test and it is the entire quality-control mechanism of self-study.
  • Keep a vocabulary notebook (one markdown file): every term you meet, one line, *grounded* ("KV cache — the K and V arrays from past tokens, kept in VRAM so generation does O(1) work per new token, size = 2 × layers × kv_heads × head_dim × seq_len × 2 bytes").

When you're stuck

  • Shape errors and NaNs are the field's compile errors; debugging them *is* the learning. Print shapes. Always.
  • Reference implementations to diff against: karpathy/nanoGPT, karpathy/minbpe, huggingface/trl, TransformerLens.
  • It is legitimate to use a frontier model as a tutor at every step. It is *not* legitimate to let it write your phase builds — the builds are the curriculum.
