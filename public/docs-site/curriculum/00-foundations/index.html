Phase 0 — Foundations: tensors, gradients, and the training loop

Goal: rebuild the muscle memory from that college ML course, but grounded so hard it can't evaporate again. At the end you can write backpropagation from scratch in pure Python and you read tensor shapes the way you read type signatures.

Time: 2–3 weeks. Hardware: laptop.

0.1 What a tensor actually is

A tensor is a contiguous block of numbers in memory, plus a shape. torch.randn(3, 4) allocates 12 float32s (48 bytes) and remembers (3, 4) so indexing works. That's the whole object. A "3D tensor of shape (32, 1024, 768)" is 32×1024×768 = 25,165,824 floats sitting in RAM (or VRAM), ~100 MB at 4 bytes each, with bookkeeping that maps x[5, 200, 3] to a byte offset.

Three facts you'll use daily:

  • dtype is bytes-per-number: float32 = 4 bytes, bfloat16 = 2, int8 = 1. Model memory math is always param_count × bytes_per_dtype.
  • A GPU is a card with its own RAM (VRAM) and thousands of weak cores that are 100–1000× faster than your CPU *at one thing*: applying the same arithmetic to huge arrays in parallel — above all, matrix multiplication. "Moving a tensor to GPU" (x.cuda()) literally copies the bytes over the PCIe bus into VRAM.
  • Shapes are your type system. A matmul (B, T, C) @ (C, D) → (B, T, D) is the field's function application. When you read a paper, you are mostly reconstructing shapes the authors didn't write down. Train the reflex now: never write a tensor op without being able to say its output shape.

0.2 What PyTorch actually is

A C++/CUDA library with Python bindings that provides exactly two services:

  1. Fast array math (the tensor ops above, dispatched to CPU or GPU kernels — a "kernel" is a small C++/CUDA function that runs one operation over an array).
  2. Autograd: as your Python code runs ops on tensors, PyTorch *records each operation* into a graph (a literal linked structure of "this tensor was produced by matmul of those two tensors"). When you later call loss.backward(), it walks that graph in reverse, applying the chain rule mechanically, and deposits into every parameter's .grad field an array of the same shape as the parameter whose entries mean: *"if you nudged this particular weight up by ε, the loss would change by ε × this number."*

That's all backprop is: chain rule on a recorded graph, done by a library. No magic, no learning-specific math — it's automatic differentiation, the same trick used in physics simulators.

0.3 What a model actually is

A model is a named collection of tensors ("parameters" / "weights") plus a function (forward) that combines an input with those tensors to produce an output. In PyTorch, model.state_dict() shows you the truth: an ordered dict like

`` transformer.h.0.attn.c_attn.weight torch.Size([768, 2304]) transformer.h.0.attn.c_attn.bias torch.Size([2304]) ... ``

"Downloading a model from Hugging Face" = downloading those float arrays serialized into a file (.safetensors, basically a header plus raw bytes). GPT-2 small has 124M parameters → 124M × 4 bytes ≈ 500 MB on disk in fp32. When a lab "ships a model," the deliverable is that file. When a paper says "we initialize from Llama-3-8B," it means they loaded that file and kept training.

So: *a model is a pure function* f(input, θ) where θ is a few GB of floats, and everything in this field is about (a) choosing the structure of f (architecture), (b) choosing θ (training), or (c) running f cheaply (inference).

0.4 What training actually is

A for-loop. Literally this, and at every scale from laptop to frontier lab:

``python for step in range(max_steps): x, y = get_batch(data) # arrays of token ids, e.g. shape (32, 1024) logits = model(x) # forward pass: a few hundred matmuls loss = cross_entropy(logits, y) # ONE scalar number loss.backward() # fill every param's .grad array optimizer.step() # nudge every param: w -= lr * (function of grad) optimizer.zero_grad() ``

A "training run" is a Python process (or thousands of coordinated processes) executing this loop for hours to months. A "loss curve" is the scalar from line 4 logged every step and plotted. "The model is learning" = that number is going down. When you read "we trained for 1M steps with batch size 4M tokens," you can now compute exactly what happened: that loop ran a million times, each iteration consuming 4M tokens.

An optimizer is a small function with state. SGD: w -= lr * grad. Adam/AdamW (the default everywhere): keeps *two extra arrays per parameter* — a running average of gradients (momentum) and of squared gradients (per-weight step-size normalization) — and updates w -= lr * momentum / sqrt(sq_avg). Memory consequence you'll meet in Phase 2: Adam triples your parameter memory.

0.5 The math you actually need (just-in-time)

Not a semester. Seven objects, each grounded in where it appears:

  1. Dot product a·b = Σ aᵢbᵢ — the similarity score between two vectors. Attention (Phase 1) is built entirely from dot products.
  2. Matrix multiply — a batch of dot products. (n,k)@(k,m): every row of A dotted with every column of B. ~All FLOPs in an LLM are this.
  3. Derivative + chain rule — d(f(g(x)))/dx = f'(g(x))·g'(x). Backprop is the chain rule applied right-to-left through the recorded graph, reusing intermediate results. You'll implement it by hand this phase; afterward it's never mysterious again.
  4. Softmax — softmax(z)ᵢ = e^{zᵢ}/Σⱼe^{zⱼ}. A function from any real vector to a probability distribution (positive, sums to 1). Appears twice in a transformer: attention weights, and final next-token probabilities. Temperature (Phase 4) is just dividing z first.
  5. Log-probs and cross-entropy — the loss in line 4 above is: *the negative log of the probability the model assigned to the correct next token*, averaged over positions. Loss 2.3 means the model put e^{-2.3} ≈ 10% on the right answer on average. Perplexity = e^{loss} ≈ "the model was choosing uniformly among ~10 tokens." Why logs? Products of many small probabilities underflow; sums of logs don't, and gradients are nicer.
  6. Expectation / variance — needed to read RL objectives (Phase 3), which are all "expected reward under the policy's distribution."
  7. KL divergence — KL(P‖Q) = Σ P log(P/Q), a number measuring how much distribution P diverges from Q; 0 iff identical. Appears as the "don't drift from the reference model" leash in RLHF.

Resources (reference, not homework): 3Blue1Brown's *Essence of Linear Algebra* + *Neural Networks* series (the best visual grounding in existence); *Mathematics for Machine Learning* (Deisenroth, free PDF) only as a lookup table.

0.6 The build

This phase's spine is Karpathy's "Neural Networks: Zero to Hero" (YouTube + karpathy/nn-zero-to-hero). It is the Lingua Latina of deep learning — he types every character on screen. Do not watch passively: pause, type everything yourself, in your own repo (mkdir llm-from-scratch — this repo lives until Phase 6).

  1. micrograd (video 1): build autograd in ~100 lines of pure Python — a Value class holding one float, its grad, and a closure that knows how to backprop through the op that produced it. Then train a tiny MLP with it. *After this, section 0.2 is something you wrote, not something you read.*
  2. makemore parts 1–3 (bigram model, MLP, activations/BatchNorm): character-level language models over a names dataset. You meet: embeddings, logits, cross-entropy, train/val split, overfitting — all at a scale where you can print every tensor.
  3. Deliverable: in your repo, *from memory, no video*: an MLP language model trained on names, plus a hand-written backward() for a softmax + cross-entropy layer (makemore part 4 walks this if stuck).

0.7 Now readable (your first graded readers)

  • Bengio et al. 2003, "A Neural Probabilistic Language Model" — the makemore MLP *is* this paper. Read it to experience the feeling this curriculum optimizes for: "I built this; the paper is just describing it formally." Note what 2003-era scale was (a 17k-word vocab was hard).
  • Karpathy's blog post "The Unreasonable Effectiveness of Recurrent Neural Networks" (2015) — pre-transformer history, pure pleasure reading; gives you the "why did everyone want better sequence models" context for Phase 1.
