Phase 3 — Post-training: from autocomplete to assistant (SFT, RLHF, DPO, reasoning)

Goal: understand and personally execute the pipeline that turns a base model into a chat/reasoning model. This is the densest paper territory of 2022–2026 and the heart of what "alignment" means in practice at labs.

Time: ~4 weeks. Cost: $20–60 (single rented 4090/A100; small open models).

Framing. Your Phase-2 model is a *simulator of internet text*: prompt it with "The capital of France is" and it completes; prompt it with a question and it might continue with *more questions* (that's what forums look like). Try this — actually sample from a base model (yours, or Llama-3.1-8B base vs. instruct) and feel the difference. Post-training is a *small* amount of training (≪1% of pretraining compute) that selects, from everything the simulator can do, a helpful-assistant persona.

3.1 Chat templates: there is no "chat," only tokens

A "conversation" hitting a model is literally one string with special tokens:

`` <|im_start|>system You are a helpful assistant.<|im_end|> <|im_start|>user What is DPO?<|im_end|> <|im_start|>assistant ``

The model just continues the string; serving code stops at <|im_end|>. "Roles," "system prompts," "multi-turn" — all formatting conventions *taught by fine-tuning*, not architecture. When an API doc says "messages array," there is a template function flattening it to exactly this. Demystify this early and a whole class of magical thinking evaporates.

3.2 SFT: supervised fine-tuning

What it is: the *identical* training loop from Phase 0, with two changes: the dataset is (prompt, good-response) pairs rendered through the chat template, and the loss is masked to response tokens only (you don't teach it to predict the user's words). A few thousand to a few million examples; hours, not weeks.

LoRA (arXiv:2106.09685), the standard cheap-tuning trick, grounded: freeze the base weights; for each big matrix W, add a learned low-rank detour W + BA where B is (d, r) and A is (r, d), r ≈ 8–64. You train ~0.5–1% as many parameters — and since optimizer state (16 bytes/param, Phase 2!) only exists for trained params, a 8B-model fine-tune fits on one 24 GB card (QLoRA quantizes the frozen base to 4-bit and gets there even faster). A "LoRA adapter" on disk is a few-MB file of those B,A matrices.

3.3 RL vocabulary, grounded in LM-land

Papers assume RL fluency; here is the dictionary with everything made concrete:

RL termIn RLHF, it is literally...
policy πthe LM being trained (its output distribution over next tokens)
actionsampling one token
trajectory / rollout / episodeone full generated completion
rewarda single scalar handed out at the end of the completion
return(here) just that scalar, maybe minus a KL penalty per token
advantage A"how much better was this than expected" — reward minus a baseline
on-policythe completions being learned from were sampled from the current model

The core move (REINFORCE / policy gradient), in one sentence: sample completions, score them, then take gradient steps that *increase the log-probability of every token in better-than-average completions and decrease it for worse-than-average ones*, proportionally to the advantage. That's it — "reinforce what worked." Everything else (PPO's clipping, GRPO's baseline, value networks) is variance-reduction and don't-blow-up machinery around that one move. Skim OpenAI's *Spinning Up in Deep RL* (intro docs) for this; you do not need classical RL (Atari, Q-learning) depth.

3.4 Reward models, and Goodhart

What a reward model (RM) physically is: your same transformer with the unembedding swapped for a 1-output linear head → f(prompt + completion) → one float. Trained on human preference pairs ("response A ≻ response B") with the Bradley–Terry loss: maximize log σ(r(A) − r(B)) — push the winner's score above the loser's. Why pairs? Humans are terrible at absolute scoring, decent at comparisons. (Your Gutenberg annotation work is *exactly* this discipline — label quality, rubric drift, inter-annotator agreement — applied to RM data. Labs employ whole teams for it.)

Goodhart/overoptimization: the RM is a lossy proxy. Optimize against it hard enough and the policy finds its errors — sycophancy, padded answers, confident hallucination ("reward hacking"). This is why every RLHF objective carries a KL-divergence penalty to the frozen reference model: a per-token leash, "win reward, but don't drift far from the SFT model." Gao et al. 2022 (arXiv:2210.10760) measured the overoptimization curves; the concept generalizes everywhere (including evals — Phase 4).

3.5 RLHF with PPO (the InstructGPT recipe)

The pipeline (InstructGPT, arXiv:2203.02155 — *the* paper that created ChatGPT-class models): pretrain → SFT → fit RM → RL against the RM. Inside the RL step, four models are in memory: the policy (training), the frozen reference (for KL), the RM (scores rollouts), and a *value network* (predicts expected reward mid-completion, used to compute per-token advantages). One iteration = generate a batch of completions (inference!), score them, compute advantages, several gradient steps. PPO's contribution (arXiv:1707.06347) is just the clipped objective: cap how far each update moves the policy per token, so the policy never leaves the region where its advantage estimates are valid. Heavy, fiddly, but the historical workhorse.

3.6 DPO: preference tuning without RL

DPO (arXiv:2305.18290) showed the RLHF objective has a closed-form trick: the optimal policy and the reward are interconvertible, so you can skip the RM and the sampling entirely and train *directly on preference pairs* with a plain supervised loss:

L = −log σ( β·[ (log π(y_w|x) − log π_ref(y_w|x)) − (log π(y_l|x) − log π_ref(y_l|x)) ] )

Read it term by term: increase the margin by which *your* model (vs. the frozen reference) prefers the chosen response over the rejected one; β controls the implicit KL leash; σ makes it Bradley–Terry-shaped. Two models in memory, no generation loop — an SFT-difficulty job with RLHF-flavored results. Tradeoff: it's offline (learns only from the dataset's responses, never its own samples), which is why labs still use on-policy RL for the hardest objectives. Variants you'll see named: IPO, KTO, SimPO — all sigmoid-of-margins cousins; don't memorize, just recognize the family.

3.7 RLAIF and Constitutional AI

Constitutional AI (Anthropic, arXiv:2212.08073) replaces most human preference labels with AI feedback: (1) have the model critique and revise its own outputs against a written list of principles (the "constitution") → SFT on revisions; (2) have a model *judge* response pairs against the principles → train the RM on those AI-made labels ("RLAIF"). Why it matters beyond cost: the spec of desired behavior becomes an auditable text document rather than ten thousand contractors' implicit judgment. This is the intellectual root of a lot of current Anthropic practice.

3.8 Reasoning models: RL with verifiable rewards

The 2024–26 frontier. The shift: replace the learned, hackable RM with rewards you can compute with a script — did the final math answer match? did the code pass the tests? Then RL directly incentivizes *whatever chain-of-thought helps the model get verified answers right*, and models learn to think longer, backtrack, and self-correct without anyone labeling reasoning steps.

  • GRPO (DeepSeekMath, arXiv:2402.03300), the algorithm that made this cheap, grounded: sample a group of G completions per prompt; advantage of each = (its reward − group mean)/group std; reinforce accordingly. The group average replaces PPO's value network — one less model in memory, embarrassingly simple.
  • DeepSeek-R1 (arXiv:2501.12948): applying pure GRPO + verifiable rewards to a strong base model ("R1-Zero") produced emergent long reasoning, reflection, "aha"-style backtracking — read the training-curve figures; this is the most important open result of 2025. The full R1 adds SFT warm-starts and distillation of reasoning traces into small models.
  • Context to slot around it: o1 (OpenAI 2024) demonstrated test-time-compute scaling (more thinking tokens → better answers, a *new scaling axis*); "Let's Verify Step by Step" (arXiv:2305.20050) for process- vs outcome-reward; STaR (arXiv:2203.14465) as the early "bootstrap reasoning from your own correct samples" ancestor.

3.9 The build (your model learns manners, then math)

Use TRL (SFTTrainer, DPOTrainer, GRPOTrainer) — read its source as you go; each trainer is a thin layer over the Phase-0 loop.

  1. SFT: take SmolLM2-135M or Qwen2.5-0.5B *base*, fine-tune on a few thousand instruction pairs (e.g. a Tulu/SmolTalk subset) with LoRA on one rented GPU. Before/after: ask both the same 10 questions. Watch an autocomplete become an assistant — the single most visceral demo in the curriculum.
  2. DPO: then train on ~5k UltraFeedback preference pairs. Implement the DPO loss yourself once (it's ~10 lines given logprobs) before using the trainer; verify they match.
  3. GRPO on grade-school math: reward = 1 if the extracted final answer equals GSM8K's, else 0 (+ a format bonus for \boxed{}). Watch accuracy and mean-completion-length curves. This is a miniature R1-Zero. (Reference: the TinyZero repro, which did R1-Zero-style training on a 3B model for ~$30.)
  4. Optional but recommended: also SFT *your own* Phase-2 124M pretrained model — completes the "one artifact" arc, even though it's too small to be a good assistant.
