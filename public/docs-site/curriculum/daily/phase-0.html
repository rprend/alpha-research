Phase 0 daily packets — Foundations (Days 1–14)

Delivers: backprop written from scratch in pure Python and fluent shape-reading. Prerequisite: none — this is the start; all you need is a laptop with Python.

Day 1 — Orientation and repo setup

⏱ ~60 min · Link: Phase 0 guide

Do: Read the curriculum README and the full Phase 0 guide top to bottom. Then create the repo that lives until Phase 6: mkdir llm-from-scratch && git init, make a Python venv, pip install torch numpy matplotlib jupyter, and create an empty vocab.md (your vocabulary notebook).

Explains: The whole field is a pure function from float arrays to float arrays, plus a for-loop that nudges the floats — everything ahead elaborates that one sentence.

Done when: Inside the repo's venv, python -c "import torch; print(torch.randn(3,4).shape)" prints torch.Size([3, 4]), and vocab.md is committed.

Day 2 — micrograd I: derivatives and the Value graph

⏱ ~75 min · Link: The spelled-out intro to neural networks and backpropagation: building micrograd

Do: Watch 0:00–51:00 (derivatives by nudging, the Value object, manual backprop on a simple expression). Pause constantly and type every character into your repo — never copy-paste (background: section 0.2 of the phase guide).

Explains: A gradient is just "nudge this input by ε and the output moves by ε × grad" — a number you can estimate by literally nudging and re-running.

Done when: Your repo has a Value class supporting + and * with a graph-drawing helper, and your hand-computed gradients for the L = (a*b + c) * f example match Karpathy's on-screen values exactly.

Day 3 — micrograd II: backward() for real

⏱ ~75 min · Link: The spelled-out intro to neural networks and backpropagation: building micrograd

Do: Watch 51:00–1:39:30 (manual backprop through a tanh neuron, _backward closures per op, topological sort, the multi-use-node gradient-accumulation bug). Type it all; deliberately reproduce the accumulation bug, then fix it with +=.

Explains: Backprop is the chain rule applied right-to-left over a recorded graph of operations — section 0.2 of the phase guide is now code you wrote.

Done when: Calling .backward() on the tanh-neuron example reproduces yesterday's manual gradients, and your grads match PyTorch autograd on the same expression to 6 decimal places (the video's comparison check passes).

Day 4 — micrograd III: train an MLP with your autograd

⏱ ~75 min · Link: The spelled-out intro to neural networks and backpropagation: building micrograd

Do: Watch 1:39:30–end (Neuron/Layer/MLP classes, the loss, the gradient-descent loop). Build the MLP on top of your Value class and train it on the 4-example dataset, watching the loss fall step by step (background: section 0.4 of the phase guide — this is the training loop, the same one frontier labs run).

Explains: Training is a for-loop: forward, one scalar loss, backward, nudge every parameter against its grad — at every scale from this 41-parameter MLP to a frontier model.

Done when: Your training loop drives loss below 0.1 on the 4-example dataset and all four predictions are within 0.1 of their targets.

Day 6 — makemore I: the bigram counting model

⏱ ~75 min · Link: The spelled-out intro to language modeling: building makemore

Do: Watch 0:00–1:02 at 1.25–1.5x, pausing to type: load names.txt, build the 27×27 bigram count matrix, normalize to probabilities, sample names, compute average negative log-likelihood.

Explains: A language model is anything that assigns a probability to the next token given context — here the entire "model" is one 27×27 array of counts you can print and read.

Done when: Your counting bigram model prints an average NLL on names.txt of 2.45 ± 0.01 and samples 10 (bad but pronounceable) names.

Day 7 — makemore I: the same model by gradient descent

⏱ ~75 min · Link: The spelled-out intro to language modeling: building makemore

Do: Watch 1:02–end at 1.25–1.5x, typing along: one-hot inputs, a single 27×27 weight matrix, logits → softmax → loss, then optimize with gradient descent instead of counting. Confirm it converges to the same answer as Day 6.

Explains: Counting and gradient descent find the same model — logits, softmax, and cross-entropy (sections 0.4 and 0.5 of the phase guide) are just the differentiable route to it.

Done when: Your gradient-trained single-layer net reaches loss ≤ 2.48 on names.txt, within ~0.03 of the counting model.

Day 8 — makemore II: the MLP language model

⏱ ~90 min · Link: Building makemore Part 2: MLP

Do: Watch the full video (1h15m) at 1.5x, pausing to type: character embeddings, a 3-character context window, hidden tanh layer, minibatches, learning-rate tuning, train/dev/test split. This is the architecture you will rebuild from memory on Day 12 — type it like you mean it.

Explains: An embedding is a lookup into a trainable float matrix, and a train/val split is how you catch a model memorizing instead of learning.

Done when: Your MLP's validation loss is below 2.30 (clearly beating the bigram's 2.45) and the script samples 20 names.

Day 9 — makemore III: initialization and activation health

⏱ ~75 min · Link: Building makemore Part 3: Activations & Gradients, BatchNorm

Do: Watch 0:00–1:00 at 1.5x, typing along: why initial loss should be −log(1/27) ≈ 3.3 and not 27, saturated tanh units, Kaiming initialization, and the activation/gradient histograms. Save the histogram plots into your repo.

Explains: Bad initialization wastes the first chunk of training and can kill neurons outright — and you can see both pathologies in a histogram before wasting a single GPU-hour.

Done when: After your init fixes, step-0 loss prints ≈ 3.3 (not 20+), and the activation-histogram plot exists as a file in your repo.

Day 10 — makemore III: BatchNorm by hand

⏱ ~75 min · Link: Building makemore Part 3: Activations & Gradients, BatchNorm

Do: Watch 1:00–end at 1.5x, typing along: implement BatchNorm1d yourself (batch mean/std normalization, gain, bias, running stats), insert it into the MLP, retrain, and study the diagnostic plots.

Explains: BatchNorm forcibly re-standardizes a layer's pre-activations every step so deeper nets stay trainable — at the cost of coupling examples within a batch.

Done when: Your hand-rolled BatchNorm1d's output passes torch.allclose against torch.nn.BatchNorm1d on a random batch, and the retrained MLP matches your Day 9 validation loss or better.
