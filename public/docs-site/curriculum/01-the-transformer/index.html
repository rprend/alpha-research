Phase 1 — The Transformer: build GPT from an empty file

Goal: build a GPT, end to end, from tokenizer to sampled text, such that you could rewrite attention() from memory on a whiteboard. Then — and only then — read the founding papers, which will read like documentation for your own code.

Time: 3–4 weeks. Hardware: laptop (minutes-long training runs).

This is the most important phase in the curriculum. Every paper you will ever read assumes fluency in exactly this material.

1.1 Tokenization: what the model actually sees

A language model never sees text. It sees a list of integers. A tokenizer is two artifacts on disk:

  • a vocabulary: a table mapping ~50k–200k strings ("chunks", like "the", " infl", "ation") to integers,
  • a set of merge rules that deterministically chop any text into those chunks.

encode: str → list[int], decode: list[int] → str, and decode(encode(s)) == s. That's the whole interface. "GPT-4 has a context window of 128k tokens" means: the function accepts a list of at most 128k integers.

BPE (byte-pair encoding), the universal algorithm: start with 256 tokens (one per byte); repeatedly find the most frequent adjacent pair in a training corpus and mint a new token for it; record the merge; repeat ~50k times. Training a tokenizer is a one-off script that runs in minutes and outputs those two artifacts.

Tokenization explains a whole genre of model weirdness you'll see referenced in papers: models are bad at counting letters ("strawberry" is 1–3 tokens, not 10 letters — the model literally cannot see the letters), arithmetic is sensitive to digit-chunking, and rare tokens with degenerate training data cause bizarre behavior (look up "SolidGoldMagikarp" for fun).

Build: implement BPE yourself, then compare with karpathy/minbpe (and his 2h tokenizer video). Then play with tiktoken to see real vocabularies. Paste text into a tokenizer visualizer until token boundaries stop surprising you.

1.2 Embeddings: integers become vectors

The first layer of the model is a matrix of shape (vocab_size, d_model) — e.g. (50257, 768) for GPT-2. "Embedding token 464" means selecting row 464. Nothing else. Each token id becomes a learned vector of 768 floats, and from here on the model is pure continuous math: input (B, T) ints → (B, T, 768) floats. (B = batch of sequences, T = sequence length.)

These rows start random and are trained like every other weight. The famous "king − man + woman ≈ queen" geometry is an *emergent property* of training, not something anyone programs in.

1.3 Attention, with no mystery

Attention answers one question: how should information move between positions in the sequence? An MLP processes each token's vector independently; attention is the only place tokens interact.

Setup: you have x of shape (B, T, C) — T token vectors of width C per sequence. Three learned weight matrices W_Q, W_K, W_V (each C × d_head) project every token vector into:

  • a query q = x @ W_Q — "what am I looking for?"
  • a key k = x @ W_K — "what do I contain?"
  • a value v = x @ W_V — "what do I offer if you attend to me?"

Then, mechanically:

``python scores = q @ k.transpose(-2, -1) / sqrt(d_head) # (B, T, T): every query dotted with every key scores = scores.masked_fill(future_mask, -inf) # causal: position t may not see positions > t weights = softmax(scores, dim=-1) # each row: a prob. distribution over past positions out = weights @ v # (B, T, d_head): weighted AVERAGE of value vectors ``

Read that as: each position computes a similarity score against every earlier position, turns the scores into percentages, and takes that weighted average of the earlier positions' value vectors. It is a *learned, differentiable dictionary lookup* — soft, so gradients flow. That's the entire trick that displaced RNNs: every pair of positions interacts directly (no information bottleneck through a recurrent state), and it's all matmuls (parallel over T at training time, GPU heaven).

The details, each one sentence: /sqrt(d_head) keeps the dot products' variance ~1 so softmax doesn't saturate at initialization; the -inf mask is what makes it a *language model* (predict token t+1 using only ≤ t — at training time all T predictions are made simultaneously, which is why one forward pass gets T loss terms); multi-head just means: do this h times in parallel with smaller d_head = C/h, concatenate the outputs — implemented as one reshape, giving the model h independent lookup channels.

1.4 The rest of the block (it's small)

A transformer is an embedding, then N identical blocks, then a final projection. Each block:

`` x = x + attention(layernorm(x)) # tokens exchange information x = x + mlp(layernorm(x)) # each token processes what it gathered ``

  • MLP: two matrices, C → 4C → C, with a nonlinearity (GELU) between. Per-token, no cross-position interaction. Two-thirds of the model's parameters live here.
  • LayerNorm: per token-vector, rescale to mean 0 / variance 1, then learned scale+shift. Pure training-stability plumbing. (Modern models use RMSNorm: skip the mean subtraction.)
  • x = x + ... (residual connections): the most underrated line. Think of x as a residual stream — a (T, C) communication bus flowing upward through the network. Every layer *reads* from the bus, computes, and *adds* its contribution back. Gradients flow through the + unimpeded (this is what makes 100-layer training possible), and — preview of Phase 5 — interpretability treats the model as many semi-independent circuits reading/writing this shared bus.
  • Positions: attention is order-blind (a set operation), so order must be injected. GPT-2: a learned (T_max, C) position-embedding table added to token embeddings. Modern models: RoPE — rotate q and k by position-dependent angles so dot products depend on *relative* distance. File it as "how position gets in"; details in Phase 2 reading.
  • Output head: final layernorm, then multiply by an "unembedding" matrix (C, vocab_size) (often the embedding transposed — "weight tying") → (B, T, vocab) logits, softmax → next-token distribution at every position.

That is the complete architecture. GPT-2, GPT-3, Llama, Claude's and Gemini's backbones — all this, with sizes and the small substitutions below.

1.5 Assemble and train it (the spine artifact)

Follow Karpathy's "Let's build GPT from scratch" video, typing it yourself into your repo, then study nanoGPT (~300 lines model + 300 training). Train the character-level model on Shakespeare: ~10 minutes on a laptop, loss falls from 4.17 (chance — recognize that number from Phase 0?) to ~1.5, and it generates plausible fake Shakespeare.

Sampling is a loop you should write by hand: forward pass → take logits at last position → softmax → draw one token id (torch.multinomial) → append → repeat. One forward pass per generated token. Notice how *wasteful* this is — you recompute everything for all previous tokens each step. Hold that thought; it becomes the KV cache in Phase 4.

This model is your Familia Romana. Name the repo's model dir, check in configs, log your loss curves. Phase 2 scales it; Phase 3 aligns it; Phase 5 dissects it.

1.6 Now readable: the founding papers

Read with your code open in a split pane; for each, the test is "can I map every paragraph onto a line of my code?"

  1. "Attention Is All You Need" (Vaswani et al. 2017, arXiv:1706.03762). One warning that defuses the most common confusion: this paper describes an encoder–decoder for translation; your GPT is decoder-only (the right half of their famous diagram, minus "cross-attention"). Everything since GPT-2 is decoder-only. Read it as history + the attention math you already know.
  2. GPT-1 ("Improving Language Understanding by Generative Pre-Training", 2018) — the thesis of the modern era in one sentence: *pretrain on next-token prediction at scale, then lightly adapt.*
  3. GPT-2 ("Language Models are Unsupervised Multitask Learners", 2019) — adds: with enough scale, you don't even need to adapt — prompt it. Your nanoGPT *is* this architecture; the paper's config table should be fully legible (you can compute its 124M params by hand — do it: embeddings + 12 blocks × (attn 4C² + mlp 8C²) + ...).
